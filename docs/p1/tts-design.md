# P1 추가 — Chris 답 음성 읽기 (TTS) 계획

작성 2026-11-20 · 상태: **T0 스파이크 완료 → A안 확정. T1 구현 완료, 앱 0.4.0 Private build 업로드(2026-11-20). 실기기 인수 TT-1~10 미실시.**
목표: G2 앱에서 Chris 답이 렌즈에 뜰 때, 같은 답을 **iPhone(스피커 또는 연결된 이어폰)으로 읽어 준다.** 읽기는 켜고 끌 수 있다.
범위: G2 앱(`app/`)의 답 읽기, 켬/끔 설정, 읽기 중지·다시 읽기. 필요할 때만 relay에 음성 파일 경로 추가(§3 B안).
비범위: Siri 단축어 경로(이미 “텍스트 말하기”로 읽음, 켬/끔은 단축어 쪽 몫), 안경 자체 소리 출력, 목소리·속도 선택 화면, 읽는 위치에 맞춘 렌즈 자동 넘김(§8 후속 후보).

## 1. 사용자 결정 (2026-11-20)

| ID | 결정 |
|---|---|
| V1 | 화면은 G2 렌즈, 소리는 **iPhone 스피커 또는 iPhone에 연결된 이어폰**. |
| V2 | 답 **전체**를 읽는다(답은 300자 이내로 요청하므로 보통 40–50초 이하). 누르기(닫기)로 즉시 멈추고, 두 번 누르기로 멈춤/처음부터 다시 읽기. |
| V3 | 읽기 설정은 **기본 꺼짐**. 회의·공공장소에서 갑자기 휴대폰 스피커로 읽지 않게 한다. |
| V4 | 켬/끔은 **안경과 휴대폰 둘 다**: 안경 첫 화면에서 아래로 쓸기, Even 앱 안 휴대폰 화면의 버튼. 설정은 휴대폰(Even 앱 저장소)에 남는다. |

## 2. 확인된 사실과 모르는 것

| 항목 | 내용 | 출처 |
|---|---|---|
| G2 스피커 | **없음.** Even 개발 문서의 하드웨어 표에 스피커 “None”. 안경은 표시·마이크·터치 입력만 | Even Hub 문서 |
| SDK 소리 출력 | **없음.** SDK 0.0.16 타입 정의에 오디오 관련은 마이크 입력(`audioControl`, `audioEvent`)뿐, 재생·TTS API 없음 | `index.d.ts` |
| 앱 실행 위치 | iPhone Even 앱 안 WebView(WKWebView). 소리를 내려면 이 WebView가 재생해야 하고, 출력 경로(스피커/AirPods)는 iOS가 정한다 | P1-design §1 |
| 단축어에서 쉬웠던 이유 | “텍스트 말하기”는 iOS가 직접 하는 단축어 동작. Hub 앱에서는 같은 iOS 음성을 **웹 표준 `speechSynthesis`** 로 불러야 한다 | siri-shortcut.md |

실기기에서 확인해야 하는 것(§5 T0 스파이크):

1. Even 앱 WebView에 `speechSynthesis`가 있고 한국어(`ko-KR`) 목소리가 잡히는가. 목소리 품질은 어떤가.
2. **안경 입력에서 시작한 재생이 막히지 않는가.** iOS WebView는 화면 터치 없이 시작한 소리 재생을 막을 수 있다. 우리 입력은 휴대폰 화면 터치가 아니라 안경 이벤트(bridge)로 들어온다. 답 도착(네트워크 응답)으로 자동 시작하는 경우도 따로 확인한다.
3. **휴대폰 잠금·Even 앱 뒤로 간 상태**에서 읽기가 시작되거나 이어지는가. 잠금 상태에서 답 표시는 이미 동작한다(P1 잠금 1분 PASS). 소리는 Even 앱의 오디오 세션 설정에 달려 있어 미지수다.
4. AirPods 연결 시 이어폰으로 나오는가. 무음 스위치를 켰을 때 스피커·이어폰에서 어떻게 되는가.
5. 읽은 뒤 G2 마이크 녹음이 정상인가. 휴대폰 오디오 세션이 바뀌어 다음 `audioControl`이 실패하거나 소리 크기(`max_rms`)가 달라지지 않는가.
6. (후속 후보용) 단어 위치 이벤트(`onboundary`)가 오는가.

## 3. 방식

**A안 — iPhone 내장 음성 (`speechSynthesis`, 제안)**
- 앱만 바꾼다. relay·Discord 변경 없음, 추가 지연 거의 없음, 소리는 휴대폰 안에서만 만들어진다.
- 위험: 위 2·3번(재생 차단, 잠금 상태). WebView가 저품질 목소리만 줄 수 있다.

**B안 — Mac이 음성 파일을 만들어 앱이 재생**
- relay에 `GET /v1/ask/{id}/speech` 추가. 기기 토큰·소유 principal·답이 있을 때만. macOS `say -v Yuna`로 m4a를 만들어 돌려준다.
- 임시 파일은 0700 폴더에 만들고 응답 직후 삭제한다(STT WAV와 같은 방식). 로그에는 글자 수·소요 시간만 남긴다.
- 앱은 Bearer 헤더로 받아 Blob → `<audio>`로 재생.
- 쓰는 경우: A안이 목소리 품질이나 재생 차단 때문에 안 될 때. 단, 잠금 상태 재생 문제는 B안도 똑같이 WebView 재생이라 해결되지 않는다.
- 비용: 300자 기준 생성 약 1초(실측 필요), 파일 크기 수백 KB.

**버린 안**
- 앱에서 단축어 실행(`shortcuts://`): Shortcuts 앱으로 화면이 넘어가고 잠금 상태에서 안 됨.
- Even AI 음성: Hub 앱에 노출되지 않음(P1-design §9 D2).

**결정 규칙 (T0 결과로 정함)**
- A안이 화면 켠 상태 + 잠금 상태 모두 통과 → A안만.
- A안이 재생 차단·목소리로 실패하고 B안은 통과 → B안.
- 둘 다 잠금 상태에서 실패 → “Even 앱이 앞에 있을 때만 읽기”로 범위를 줄이고 사용자에게 보고한다. 잠금 상태 실패를 성공으로 적지 않는다.

**T0 결과 (2026-11-20, device-test-plan §1.5)**
- 한국어 목소리 2개(`Yuna` 선택).
- 안경 입력만으로 시작한 재생이 막히지 않음(A·B 모두).
- 10초 타이머 시작, 휴대폰 잠금 상태 시작, 300자 읽기 중 잠금 모두 동작.
- 읽은 뒤 G2 마이크 정상.
- → 결정 규칙대로 **A안만** 쓴다. relay 변경(T2) 없음.
- 남은 확인(AirPods, 무음 스위치)은 인수 TT-4·TT-8에서.

## 4. 앱 동작 (A안 기준, B안도 재생 부분만 다름)

**설정**
- `bridge.setLocalStorage('g2relay.speak', '1' | '0')`. 값이 없으면 꺼짐(V3).
- 시작할 때 읽어 상태에 둔다.

**켬/끔 (V4)**
- 첫 화면(idle)에서 아래로 쓸기를 하면 바뀐다. 지금은 비어 있는 입력이다.
- 렌즈 note에 “음성 읽기 켬”/“음성 읽기 끔”을 보여 준다.
- 첫 화면 안내에 줄을 추가한다: `아래로 쓸기 = 음성 읽기 (지금: 꺼짐)`
- 휴대폰 화면(`index.html`)에 같은 기능의 버튼을 둔다(현재 상태 표시).

**언제 읽나**
- 새 답이 도착해 렌즈에 뜰 때 자동으로 읽는다. 조건: 설정 켬 + `reply_available`. `send`/`poll` 결과이며, 늦은 답 포함.
- 지난 답 다시 보기(위로 쓸기 → `showLast`)는 자동으로 읽지 않는다. 두 번 누르면 읽는다.
- 오류·대기 안내 문장은 읽지 않는다. 렌즈로 충분하고, 읽으면 회의 중 소리 위험이 커진다.

**답 화면(reply) 입력 변경**

| 입력 | 지금 | 바뀐 후 |
|---|---|---|
| 누르기 | 닫기 | 닫기 + 읽기 즉시 멈춤 |
| 두 번 | 한 페이지 답이면 닫기, 여러 페이지면 없음 | 읽는 중이면 멈춤, 아니면 처음부터 읽기 (설정이 꺼져 있어도 이 답만 읽음) |
| 위·아래 | 페이지 넘기기 | 그대로 (읽기는 계속) |

**겹침 방지**
- 녹음 시작(첫 화면 누르기) 전에 항상 읽기를 멈춘다. 휴대폰 스피커 소리가 안경 마이크에 섞이지 않게 하려는 것이다.
- 새 답이 오면 이전 읽기는 취소한다.

**렌즈 표시**
- 읽는 동안 머리줄에 `· 읽는 중`을 붙인다(예: `Chris 답 1/2 · 읽는 중`).
- 아이콘 문자(🔊 등)는 G2 글꼴에 없을 수 있어 쓰지 않는다.

**읽을 문장 다듬기**
- relay가 준 `reply`(요청 ID·마크다운 이미 제거, `cleanReply`)를 쓴다.
- 앱에서 순수 함수 `speechText()`로 한 번 더 다듬는다:
  - URL → “링크”
  - 이모지·장식 기호 제거
  - 줄바꿈 → 쉼표·마침표 흐름
  - 연속 공백 정리
- 이 함수는 `tests/`에서 단위 시험한다.

**목소리**
- `ko-KR` 목소리 중 이름에 enhanced/premium이 있으면 우선 고른다. 없으면 첫 번째 한국어 목소리를 쓴다.
- 속도는 1.0 고정(후속 조정 후보).
- 한국어 목소리가 없으면 읽지 않고 휴대폰 로그와 렌즈 note에 알린다.

**휴대폰 로그 (본문 없음)**
- `읽기 시작 n자`, `읽기 끝 n초`, `읽기 멈춤`, `읽기 실패 <이유>`

**서버 변경 (A안)**
- 없음.
- 선택: “답 → 읽기 시작” 지연을 재려면 `displayed`와 같은 방식의 `spoken` 이벤트를 나중에 추가할 수 있다. 이번 범위에서는 휴대폰 로그로만 본다.

## 7. 보안·개인정보

- A안: 답 문장은 이미 휴대폰에 와 있고, 소리는 iPhone 안에서 만들어진다. 새로 나가는 데이터 없음.
  - iOS 목소리 엔진이 외부로 보내는지는 Apple 정책을 따른다. 내장 목소리는 기기 안에서 처리된다.
- B안: Mac 안에서 생성, 파일은 응답 후 삭제. 기존 기기 토큰 범위를 그대로 쓴다(남의 요청 404).
- 로그에 답 본문을 남기지 않는 원칙 유지(글자 수·초만).
- 위험: 켜 둔 채로 사람 많은 곳에서 답이 스피커로 나올 수 있다. 기본 꺼짐(V3)과 렌즈의 `· 읽는 중` 표시, 누르기 한 번 즉시 멈춤으로 줄인다.

## 8. 후속 후보 (이번 범위 아님)

- 읽는 위치에 맞춰 렌즈 페이지 자동 넘김(`onboundary` 지원 시).
- 읽기 속도·목소리 선택(휴대폰 화면).
- “이어폰 연결 시에만 읽기” 옵션. WebView에서 출력 경로를 알 수 있는지부터 확인 필요.
- `spoken` 이벤트로 “말 끝 → 읽기 시작” 지연 기록.

## 9. AirPods 대신 iPhone 스피커로 나오는 문제 (2026-11-20 사용자 보고, 조사 중)

증상: AirPods를 끼고 있어도 가끔 읽기가 iPhone 스피커로 나온다.

추정 원인 (미검증):
1. **Even 앱의 iOS 오디오 세션.** WebView 소리는 호스트 앱(Even 앱)의 AVAudioSession 카테고리를 따른다. 입력·출력을 함께 쓰는 모드(play-and-record)에서 블루투스 고음질(A2DP) 출력을 허용하지 않으면 AirPods가 빠지고 스피커로 간다. Even 앱이 마이크·자체 기능 때문에 그 모드로 바꾼 순간에만 생긴다면 “가끔”과 맞는다.
2. **AirPods 자동 전환.** 같은 Apple ID의 Mac 등으로 AirPods가 넘어가 iPhone에 연결이 없을 때.
3. 한쪽을 뺐거나 재연결 중.

조치:
- 앱 0.4.1 (Private build 업로드):
  - 읽을 때마다 휴대폰 로그에 `읽기 요청 녹음 끝 후 Ns · 화면 … · playback 고정 …`와 `읽기 준비 오디오 <type>/<state>`를 남긴다.
  - 휴대폰 화면에 **“오디오 playback 고정”** 버튼(기본 끔, 설정 저장)을 둔다. 켜면 읽는 동안만 `navigator.audioSession.type = 'playback'`을 요청하고, 끝나면 원래 값으로 돌린다.
  - 주의: playback은 다른 앱 음악을 멈출 수 있다.
- 스파이크 `tts-spike` 0.2:
  - 렌즈와 로그에 오디오 세션 값을 보여 준다.
  - 버튼으로 세션 type을 차례로 바꾼다(auto → playback → ambient → play-and-record → transient → transient-solo).
  - “녹음 3초 → 바로 A”(안경 길게 누르기도 같음)로 녹음 직후 읽기를 재현한다.
